# 会計システム並行入力テスト用 仕訳データ

弥生会計と自社開発会計システムに**同じ仕訳**を入力し、集計結果が一致するかを確認するためのテストデータ。

## ファイル

| ファイル | 用途 |
|---|---|
| `generate.py` | 仕訳定義と出力処理。データを変えるときはここを編集して `python3 generate.py` を実行 |
| `output/yayoi_import.csv` | 弥生会計の仕訳日記帳インポート用（Shift_JIS・ヘッダーなし・25項目） |
| `output/journal_canonical.csv` | 自社システム投入用。1明細1行（借方・貸方を別行）、UTF-8 BOM付き |
| `output/expected_trial_balance.csv` | 期待値: 勘定科目別の借方合計・貸方合計・残高、当期純損益 |
| `output/expected_sub_accounts.csv` | 期待値: 補助科目別残高 |
| `output/expected_tax_summary.csv` | 期待値: 税区分別の件数・税込金額・消費税額 |

## 前提条件（両システムで揃えること）

- 会計期間: 2026/04/01 開始（テスト対象は 2026年4月分）、**期首残高ゼロ**
- **税込経理方式**
- 消費税額は税込金額から逆算し **1円未満切り捨て**（例: 1,099円 × 10/110 = 99.9 → 99円）
- 部門: `本社` `営業部` を事前登録
- 補助科目を事前登録: 普通預金（みずほ銀行・三井住友銀行）、売掛金（A商事・B物産・海外C社）、買掛金（D卸）、預り金（源泉所得税・住民税・社会保険料）

## チェック手順

1. **取込**: 弥生に `yayoi_import.csv` をインポートし、自社システムに `journal_canonical.csv` を投入（または手入力）する。
2. **件数**: 両システムの仕訳件数が 26伝票・57明細になっているか。取込エラー・スキップが出ていないか。
3. **試算表**: 両システムの残高試算表を出力し、`expected_trial_balance.csv` と科目ごとに突き合わせる。
4. **補助科目**: 補助科目別残高を `expected_sub_accounts.csv` と照合（特に売掛金A商事が 0 に消し込まれているか）。
5. **消費税**: 税区分別集計表を `expected_tax_summary.csv` と照合。差異がある場合は端数処理（No.5・15・24）と、税率混在伝票（No.10）を最初に疑う。
6. **表示・文字**: No.13（カンマ入り摘要）と No.25（32文字の摘要）が欠けずに表示されるか、No.26 の桁あふれがないか。
7. **部門**: 部門別損益で 本社・営業部 に正しく配賦されているか。

## 注意

- 弥生の税区分名はバージョンやインボイス制度の設定によって異なる場合がある（例: `課対仕入込10%適格`）。取込エラーになる場合は `generate.py` の `TAX` 辞書の名称を環境に合わせて変更し、再生成する。
- `yayoi_import.csv` には消費税額を明示している。弥生側で税額を自動計算させたい場合や、端数処理設定の違いを検証したい場合は、税額列を空欄にして取り込み、結果を期待値と比較する。
